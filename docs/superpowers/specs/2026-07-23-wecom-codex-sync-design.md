# 企业微信与 Codex 双向同步设计

## 目标

在现有 Codex、飞书、个人微信精简版中增加企业微信入口，并尽量对齐飞书的核心体验：

- 一个企业微信群稳定绑定一个 Codex 会话；
- 企业微信群消息进入对应 Codex 会话；
- Codex App 中的用户消息和 Codex 回复回传到原企业微信群；
- 文本、图片和文件双向传输；
- 进程重启或企业微信长连接恢复后继续使用原绑定；
- 不改变飞书、个人微信及其既有会话。

企业微信第一版只接入官方“智能机器人 WebSocket 长连接”模式。HTTP Webhook、自建应用群聊、外部联系人群和桌面自动化不在本次范围内。

## 平台边界

企业微信智能机器人与飞书机器人存在一项无法消除的官方能力差异：智能机器人不能通过现有开放接口主动创建一个自己可继续接收消息的新群。

因此企业微信采用以下固定规则：

1. 用户手动创建企业微信内部群并添加智能机器人。
2. 用户在群内首次 `@机器人` 发送消息时，cc-connect 创建对应 Codex 会话。
3. 同一群内不同成员的消息始终进入同一个 Codex 会话。
4. 另建一个群并添加机器人，就得到另一个独立 Codex 会话。
5. 群内消息需要 `@机器人` 才能由企业微信推送给 cc-connect。
6. 企业微信中的 `/new` 不修改当前绑定和上下文，只回复“手动新建群、添加机器人、发送首条消息”的引导。

单聊采用“一位企业微信用户对应一个 Codex 会话”，不提供同一用户下的多个单聊会话。

## 会话标识与命名

平台名称统一使用 `wecom`，避免与现有个人微信 `weixin` 混淆。

- 群聊会话键：`wecom:g:{chatID}`
- 单聊会话键：`wecom:u:{userID}`
- 工作区通道键与会话键保持同一群或同一用户稳定，不包含消息发送者。

企业微信长连接回调只保证提供 `chatID`，不保证提供可读群名。Codex 会话标题使用：

- 群聊：`[企业微信-Codex] 企业微信群-{chatID短标识}`
- 单聊：`[企业微信-Codex] {userID短标识}`

该规则保证标题可区分且重启后稳定，不通过额外通讯录权限猜测群名。已有飞书和个人微信会话名不迁移、不重命名。

## 架构

### 企业微信平台适配器

从上游 cc-connect 的 `platform/wecom` 中提取 WebSocket 模式所需的最小实现，并改为当前仓库模块路径。保留：

- BotID、Secret 订阅认证；
- 30 秒心跳；
- 指数退避重连；
- 消息 ID 去重和旧消息过滤；
- 文本、语音转写文本、图片和文件接收；
- 文本、图片和文件回复及主动发送；
- 发送确认与超时处理。

不带入旧 Webhook 模式所需的 CorpID、AgentID、回调加解密、公网端口和代理逻辑。

适配器额外实现当前精简版需要的能力：

- `ReplyContextReconstructor`：从稳定会话键恢复群聊或单聊发送目标；
- `ExternalConversationRelayTarget`：允许 Codex App 转录事件回传企业微信；
- `FormattingInstructionProvider`：约束企业微信消息格式；
- 平台连接状态通知：只有订阅成功后才标记可发送，断线后标记不可用；
- 同一会话的入站顺序控制，避免并发消息创建或路由到不同 Codex 会话。

### 核心路由

企业微信适配器在构造消息时直接给出不含发送者的群聊会话键，因此不修改飞书和微信的通用路由逻辑。

第一条有效消息按现有会话管理流程创建 Codex 会话并持久化绑定。后续消息、重启恢复、Codex App 反向同步、定时任务和附件回传均通过同一稳定键定位企业微信目标。

`/new` 继续使用平台能力分支。企业微信返回明确的人工建群引导，并保证：

- 当前群会话不清空；
- 当前群绑定不改写；
- 不创建幽灵 Codex 会话；
- 重试不会重复发送多条引导。

### 配置与安装

配置示例：

```toml
[[projects.platforms]]
type = "wecom"

[projects.platforms.options]
mode = "websocket"
bot_id = "your-wecom-bot-id"
bot_secret = "your-wecom-bot-secret"
allow_from = "*"
```

新增 `cc-connect wecom setup`，支持交互输入及参数方式写入 BotID、Secret 和允许用户，不在日志中打印 Secret。

macOS 安装向导保留原有 1 至 3 选项含义，并增加：

1. 飞书
2. 个人微信
3. 飞书 + 个人微信
4. 企业微信
5. 飞书 + 企业微信
6. 个人微信 + 企业微信
7. 全部平台

企业微信配置完成后，向导提示用户到管理后台创建智能机器人、选择 API 长连接模式并取得 BotID 与 Secret。安装过程不申请公网权限，不安装隧道工具。

## 数据流

### 企业微信到 Codex

1. WebSocket 收到群聊 `@机器人` 或单聊消息。
2. 校验消息时间、消息 ID 和 `allow_from`。
3. 群聊按 `chatID`、单聊按 `userID` 生成稳定会话键。
4. 下载并解密图片或文件。
5. 将消息按会话顺序交给核心引擎。
6. 核心恢复或创建对应 Codex 会话并处理消息。
7. 回复通过原回调请求或主动发送接口返回相同企业微信会话。

### Codex App 到企业微信

1. 桌面同步轮询只跟踪已绑定的企业微信 Codex 会话。
2. 从会话键恢复 `chatID`、会话类型和发送上下文。
3. 使用企业微信主动发送接口回传 `✣ Codex App · 你` 或 `✣ Codex · 回复` 内容。
4. 仅在企业微信确认发送成功后推进同步游标；失败或断线时保留待发送事件，连接恢复后重试。

## 错误处理

- 认证失败：停止当前连接重试风暴，日志只显示错误类型，不显示 Secret。
- 临时断线：标记平台不可用并指数退避重连；未确认的桌面同步消息不丢弃。
- 重复回调：按消息 ID 去重。
- 媒体下载或解密失败：记录精简错误，文本部分仍可处理；纯媒体失败时向用户返回可理解提示。
- 主动发送受限：保留待发送事件并按现有重试机制处理，不把失败标记为已送达。
- 未激活会话：如果企业微信尚未允许主动推送，提示用户先在目标群 `@机器人` 发送一条消息。
- `/new`：只返回建群引导，不执行任何会话写操作。

## 测试

### 平台单元测试

- 群聊中不同用户得到同一个会话键；
- 不同群得到不同会话键；
- 单聊用户之间互相隔离；
- 消息去重、旧消息过滤和入站顺序；
- 断线、心跳、重连和认证失败；
- 文本、图片、文件收发；
- 主动发送确认失败时返回错误；
- 会话上下文可从持久化键恢复；
- `/new` 引导不修改当前会话。

### 核心回归测试

- 企业微信首条消息只创建一个 Codex 会话；
- 同群并发消息不串会话；
- Codex App 用户消息与回复回到正确企业微信群；
- 断线期间的桌面消息在恢复后继续发送；
- 多工作区重启后恢复企业微信绑定；
- 飞书 `/new` 自动建群及个人微信逻辑保持不变。

### 安装与公开包测试

- `wecom setup` 不泄露 Secret，重复运行安全更新同一配置；
- 安装向导 1 至 7 的平台组合正确；
- 示例配置、README、中英文安装说明和公开包内容一致；
- 隐私扫描不包含真实 BotID、Secret、会话或登录状态。

## 实机验收

在真实企业微信环境完成一次受控验收：

1. 创建 A 群和 B 群并分别添加机器人。
2. A 群两位成员分别 `@机器人`，确认只出现一个 A 群 Codex 会话。
3. B 群发送消息，确认创建独立 B 群 Codex 会话。
4. 在两个 Codex 会话分别发送消息，确认只回到各自企业微信群。
5. 验证图片和文件各一次。
6. 断开并恢复网络，确认连接恢复且待发送消息不丢失。
7. 重启服务，确认 A、B 群仍绑定原 Codex 会话。
8. 在 A 群执行 `/new`，确认仅出现建群引导，A 群上下文不变。

实机验收需要用户在企业微信后台创建智能机器人并提供本机配置所需的 BotID 与 Secret；凭据只写入本机正式配置，不进入仓库、测试夹具或报告。

## 明确不做

- 不通过自建应用 API 自动创建企业微信群；
- 不支持企业微信外部联系人群；
- 不加入 HTTP Webhook 或公网隧道；
- 不使用桌面 UI 自动化模拟建群；
- 不改造企业微信官方客户端；
- 不迁移或重命名现有飞书、个人微信会话；
- 不恢复上游其他智能体、平台、Web 管理端或 npm 分发层。
